# 菜单管理

组件约定见 [COMPONENT-REFERENCE.md](COMPONENT-REFERENCE.md)。页面沿用原来的 ArtSearchBar、ArtTableHeader、ArtTable 和 860px 双列 ArtForm 弹窗。

## 数据来源

侧栏和动态路由只使用 `GET /sys-permission/getCurrentUserMenus` 返回的数据库菜单，结合当前账号权限和平台/商户视角展示。已移除 `supplementalMenus`，不再补充数据库中不存在的“运营工具”、工作台、个人中心或平台入口。没有可用菜单时进入 403，不自动补出业务菜单。

`sys_permission` 定义全局菜单，`sys_role_permission` 分配角色权限。菜单管理显示完整定义；侧栏显示当前账号可用的部分。新增菜单后仍需在角色管理中分配。禁用的目录会连同下级一起隐藏；权限按钮/API不作为侧栏页面显示。

## 调整方法

- 点击“调整层级 / 排序”：拖到条目上下方进行同级排序，拖到目录中修改归属，拖到“顶层菜单”可移到根层级。
- 点击“保存调整”才提交。取消不保存，重置恢复打开弹窗时的数据。保存失败时保留调整结果。
- 新建/编辑菜单可以搜索选择“上级菜单”。“组件地址”按页面中文名称或路径搜索，选择已有页面自动填写路由；新建时还补齐空的名称和权限编码。
- 页面选项来自主项目 `src/views/**/index.vue`（排除认证、异常、示例子组件等），只用于编辑器，不会自动加入侧栏。
- 原页面URL保持不变；批量保存时，历史相对地址转换为移动前的完整地址。嵌套目录使用 RouterView，不重复渲染应用侧栏和顶栏。
- 全局菜单移动会影响使用该菜单的所有角色的导航层级，原角色授权保持不变。后端只补齐已授权页面的有效目录祖先，不追加兄弟页面或按钮权限。

## 保存接口

`PUT /sys-permission/hierarchy` 仅允许 SUPER_ADMIN。

请求中的 `original` 和 `nodes` 都是完整条目列表，每项为 `{ id, parentId, sort }`，ID 使用字符串保持 Java Long 精度。

后端在事务中锁定菜单快照，验证重复/缺失ID、并发层级修改、非法父级、循环和深度；只更新层级、顺序和必要的完整路由。中途写入失败抛出异常，事务整体回滚。页面不能作为其他菜单的目录，按钮/API不能移到顶层。保存成功后重新加载侧栏与注册路由。
