# 会员等级体系与模拟数据

等级数据存放在 `liteshop_user.user_level_scheme`（体系）和 `liteshop_user.user_level`（等级）。平台模板的 `tenant_id` 为 NULL，商户副本的 `tenant_id` 为所属租户 ID。每个租户同时启用一套，允许保留其他备用方案。

## 使用步骤

1. 若数据库还没有 `user_level_scheme` 表，先执行后端的 `sql/vertical-split/12_member_level_schemes.sql`，它也会增加平台等级模板菜单及超级管理员授权。已经执行过则无需重复新增菜单。
2. 在开发库手动运行 [14_member_level_demo.sql](sql/14_member_level_demo.sql)，生成餐饮和零售两套示例，各 5 个等级。权益为文案示例，不会自动配置折扣、积分倍率或发券规则。
3. 超级管理员退出商户作用域，进入平台管理的会员等级模板页面，选择体系，点击“设为平台默认体系”。已有默认选择不会被模拟 SQL 替换。
4. 创建商户时页面展示默认体系名称。后端在创建租户的同一事务中初始化角色、复制默认体系和全部等级并启用；任何复制失败都会回滚租户创建。尚未设置有效平台默认时会拒绝创建，避免生成缺少等级配置的租户。
5. 租户等级页展示当前生效体系；“采用平台默认体系”会复制当前默认并启用，保留原方案。切换时按会员原经验重新计算等级，经验、积分和余额保持不变。

## 默认行为

- 新租户持有创建时的平台默认体系副本，后续独立调整。更换平台默认不会更新这些副本。
- 旧租户没有启用且有效的方案时，会员等级列表、按经验匹配、按编码查询和下一级查询均回退到当前有效的平台默认体系；不会借用其他租户的数据。
- 已启用租户自有体系时，仅从该体系查找等级。某个编码不存在不会再去平台默认拼凑。
- 平台默认方案必须处于启用状态，并含一个启用的零经验等级；同一方案中启用等级的经验门槛必须唯一。
- 基础业务配置仍由现有租户创建事件初始化；若配置服务暂不可用，现有机制在首次读取时补齐。等级与角色初始化在用户服务本地事务内完成。

## 模拟 SQL 的可选租户复制

默认 `@demo_tenant_id = NULL`，只插入平台模板与等级。改为已有测试租户 ID，并选择餐饮或零售模板 ID，可为没有启用体系的测试租户复制一套；已有启用方案会跳过。脚本不创建租户或账号，不影响已选体系；请在开发环境暂停等级写入后执行。

## 部署

前端与配套用户服务代码需要一起部署。用户服务新增 `POST /user-level/schemes/use-default`；原有设置平台默认接口继续使用 `POST /user-level/schemes/{id}/default`。本次未执行连接真实数据库的 SQL，也未替换正在运行的服务。

## 指定租户可选体系

新增版本需先执行 [15_member_level_template_grants.sql](sql/15_member_level_template_grants.sql)，再重新构建并重启用户服务。菜单沿用平台会员等级模板入口，无需新增菜单。

1. 超级管理员退出商户作用域，在平台等级管理中选择一个体系，点击“分配给租户”。
2. 搜索并多选目标租户，保存分配。一个体系可分配给多个租户，一个租户也可获得多个候选体系。
3. 租户等级管理的下拉列表会显示自有方案、平台默认和已分配的平台体系。平台体系可只读预览，点击“选用这套体系”后会复制为独立方案并启用。
4. 平台当前默认体系对所有租户可用；默认体系的分配名单在以后切换默认时仍保留指定租户的选择权。
5. 取消分配只取消后续预览、复制和选用的权限，不删除租户已有副本，不切换当前生效方案。

后端同时检查列表、详情预览、复制来源和选用请求。未分配租户不能仅靠修改 URL 或请求参数使用其他模板。分配接口仅允许平台作用域的超级管理员使用。

分配关系保存在 `liteshop_user.user_level_template_tenant`；本次迁移不向所有租户批量授权非默认模板，已复制的租户方案继续可用。
